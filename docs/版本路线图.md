# 版本路线图（收口版）

## 一、当前策略

现在项目不再追求把所有想法都做完，而是进入**收口模式**：

- 先把主方法收成一个能写论文、能讲清楚的闭环
- 代码只保留真正影响论文主线的版本
- 论文写作和实验整理要尽早并行
- 后面那些更花时间的扩展，全部降级为“有时间再做”

核心主线不变：

**逐步提升 PINN 对光污染背景的物理建模能力与可分离能力。**

---

## 二、收口路线图（7/19 - 8/5）

### 目标

在 8 月上旬前，把项目收成一个**最小可写论文版本**。

| 模块 | 这段时间只做什么 | 暂时不要做什么 | 预期产出 |
|---|---|---|---|
| V3：可学习 `alpha` | 稳定可学习 `alpha` 链路；统一 `I_city` 与 `alpha` 的调用关系；跑通一个能稳定出图的训练脚本 | 不再追求把 `alpha` 解释成严格物理真值；不再无限扩展参数搜索 | 一个稳定的主训练脚本；一组可重复的 `alpha` 曲线与 loss 图 |
| V4：`I_city` 优化版 | 先增强 `I_city` 的表达能力和稳定性；先做最小可讲版本；后续再视实验决定是否继续加范围项/几何项 | 不急着定死复杂几何；不做大规模重构 | 一个能讲清楚的 `I_city` 版本；一版可用于论文说明的方法图 |
| 实验收口 | 只保留必要实验：合成图、真实图、最基础的对比图、能支撑论文主线的图表 | 不再开新的大版本；不再随意扩展 RGB、贝叶斯、傅里叶等新分支；不把精力分散到工程化大改上 | 一组能支撑论文主线的基础实验结果 |

## 三、决赛路线图（8/6 - 9/15）

### 目标

把项目从“代码原型”推进到“能提交论文”的状态，并给论文写作留出足够时间。

| 时间段 | 阶段 | 主要任务 | 输出要求 |
|---|---|---|---|
| 8/6 - 8/20 | 论文初稿阶段 | 合作伙伴先写论文初稿；你重点盯住方法部分和公式部分；同步检查题目、方法描述、公式推导、实验图是否和代码一致 | 有一版完整初稿；方法与公式口径统一 |
| 8/21 - 9/5 | 实验补齐阶段 | 补缺失图表；补必要对比；补论文里最容易被问到的细节；重点检查论文有没有写偏或说大 | 图表补齐；结论与实验一致；边界说明更稳 |
| 9/6 - 9/15 | 定稿阶段 | 只做收尾和修改；不再加新功能；不再改大方向；把提交版本锁死 | 提交版论文 + 锁定代码与实验结果 |

### 决赛阶段核心任务表

| 核心任务 | 要求 |
|---|---|
| 把论文讲清楚 | 方法主线、公式来源、版本演化都能说清楚 |
| 把实验结果讲稳 | 图表能支撑结论，不靠模糊描述硬撑 |
| 把方法边界讲诚实 | 明确小角度、局部近似、effective alpha 等限制 |
| 把项目从“能跑”变成“能交” | 代码、图表、论文叙述三者口径一致 |

## 四、版本总览（保留 ideas）

> 这一部分保留你的原始版本构想，作为后续扩展 ideas 使用。当前不要求全部做完，但不能删，因为它们是项目思路库。

### V1：实现基础算法

**目标**：完成 PINN 光污染分离原型的最小闭环。

**内容**：
1. 坐标输入 MLP
2. 数据损失 + 物理损失联合训练
3. autograd 拉普拉斯
4. 灰度图训练与预测
5. 输出观测图 / 预测图 / 残差图

**定位**：基础主链路。

---

### V2：实现可学习 I_city

**目标**：让光污染源项不再只是固定常数，而是可训练模块。

**内容**：
1. 用粗模糊结果初始化源中心
2. 让源中心 `(x, y)` 可学习
3. 用 PDE 残差反向更新源位置
4. 把解析公式驱动的 `I_city` 接进损失

**定位**：结构化物理建模。

---

### V3：实现可学习 alpha

**目标**：把固定的 `alpha` 改成受约束的可学习 PDE 系数。

**内容**：
1. 引入有界可学习参数
2. 用 sigmoid 限制取值范围
3. 在损失中替换固定 `alpha`
4. 做固定 vs 可学习的对比实验

**定位**：低工作量、高优先级。

---

### V4：优化 I_city

**目标**：增强 `I_city` 的表达能力和稳定性，让它更接近真实光污染背景的空间形态。

**内容**：
1. 优化 `I_city` 的参数化方式
2. 视实验情况尝试加入高斯包络或其他空间先验
3. 对比不同 `I_city` 形式对分离效果的影响
4. 观察它对真实数据的拟合稳定性

**定位**：在不强行定死几何形式的前提下，先把源项建模做扎实。

---

### V5：实现 RGB-aware 训练与损失

**目标**：利用颜色信息减少星云 / 银河缓变结构误判。

**内容**：
1. 灰度扩展到 RGB
2. 单通道损失扩展到三通道
3. 物理损失先约束亮度 / 灰度分量
4. 引入天空区域 mask，排除建筑物和地景

**定位**：真实场景适配。

---

### V6：实现预训练与参数保存

**目标**：让 PINN 能续训、能回滚、能复现实验。

**内容**：
1. 保存模型参数
2. 支持 checkpoint 加载
3. 先 data loss、后 physics loss 的预训练策略
4. 对比从零训练与预训练初始化

**定位**：训练效率和工程稳定性。

---

### V7：系统实验与消融

**目标**：整理成论文级证据链。

**内容**：
1. 合成数据实验
2. 真实 RAW 数据实验
3. 固定 alpha vs 可学习 alpha
4. 点源 I_city vs 范围 I_city
5. 灰度训练 vs RGB-aware 训练
6. 从零训练 vs 预训练初始化
7. 不同损失权重与边界条件消融

**定位**：论文前必须完成的证据链。

---

## 五、版本推进顺序（收口后）

当前实际推进顺序建议改成：

1. **V3：可学习 alpha**
2. **V4：I_city 范围学习**
3. **论文初稿同步开始**
4. **必要时补 V5 的简单 mask / RGB 适配**
5. **V6 / V7 只在时间够的时候做，不作为硬目标**

---

## 六、最后的总原则

这份路线图现在只遵守三条：

1. **先收口，再扩展**
2. **先能写论文，再追求更完整版本**
3. **任何新 idea 先问一句：它会不会拖慢 9/15 的提交**

如果会，那就先放后面。
